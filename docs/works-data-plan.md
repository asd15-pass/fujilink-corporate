# 施工実績データの取り込み方針（未着手）

施工実績のデータはスプレッドシートで受け取る。公開先はお名前.com のサーバーで Node を動かせないため、`output: "export"` で静的に書き出す前提で組む。

現状は `src/lib/site.ts` の `WORKS` に仮データを生成している。以下は実装前の想定であり、まだ着手していない。

## 全体の流れ

```
スプシ（CSVとして公開）
   │  next build の最初に取得
   ▼
works.json を生成 → /works と /works/1, /works/2 … を静的HTMLに書き出し
   │
   ▼
GitHub Actions が FTP でお名前.com にアップロード
```

1. **スプシを読む**: シートを「ウェブに公開（CSV）」にし、ビルド前に CSV を取得して JSON に変換するスクリプトを置く。`WORKS` の仮データをこれに差し替える。詳細ページ（`src/app/works/[id]/page.tsx`）は `generateStaticParams` で全件を書き出す作りなので、ほぼそのまま使える。
2. **一覧の絞り込みをブラウザ側に移す**: `src/app/works/page.tsx` は `searchParams` をサーバーで読んでいるため、静的書き出しでは動かない。フィルター部分だけ `'use client'` のコンポーネントに切り出し、`useSearchParams` で `?ind=飲食店&tag=看板` の URL を読み書きする。URL の形式は今のまま変えない。数百件程度なら全件を一度に読み込んでよい。
3. **更新の流れ**: GitHub Actions に「ビルドして FTP でアップロード」する workflow を作る。実行のきっかけは手動実行・定時実行・スプシ側の Apps Script からの呼び出しのいずれか。

写真は Google Drive の共有リンクを使わない（表示が不安定になる）。スプシにはファイル名だけを書き、写真は `public/works/` に置く。

## シートの列

1行が1件の実績。1行目は見出し行にする。

| 列名 | 必須 | 形式・入力ルール | 使う場所 |
| --- | --- | --- | --- |
| ID | ○ | 半角数字。重複させず、一度決めたら変えない | 詳細ページの URL（`/works/12`） |
| 公開 | ○ | プルダウン（公開 / 非公開） | 非公開の行は書き出さない |
| 案件名 | ○ | 30字程度まで | 一覧カード・詳細ページの見出し・ページタイトル |
| 業種 | ○ | プルダウン。1件につき1つ | 一覧の「業種」絞り込み・カード・詳細 |
| タグ | ○ | プルダウン（複数選択）またはカンマ区切り | 一覧の「タグ」絞り込み・詳細の「施工内容」・関連実績 |
| 施工日 | ○ | `2026/10/20` 形式 | 一覧の並び順（新しい順）・詳細の日付 |
| 概要 | ○ | 2〜3行 | 詳細の「案件概要」 |
| 施工のポイント | | 数行。ご要望・工夫した点・お客様の声など | 詳細の「施工のポイント」 |
| メイン写真 | ○ | ファイル名（例 `012-main.jpg`） | 一覧カード・詳細のメイン写真 |
| 施工前写真 | | ファイル名 | 詳細の写真欄 |
| 施工後写真 | | ファイル名 | 詳細の写真欄 |
| サブ写真 | | ファイル名 | 詳細の写真欄 |
| トップ掲載 | | プルダウン（する / 空欄）。3件まで | トップページの施工実績 |

業種とタグは絞り込みに使うため、データの入力規則でプルダウンにして表記ゆれを防ぐ。選択肢の初期案は `src/lib/site.ts` の `INDUSTRIES` / `WORK_TAGS`。

所在地（市区町村まで）・施工面積・工期などを載せる場合は列を追加し、詳細の「案件概要」の表に行を足す。
